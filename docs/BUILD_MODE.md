# BUILD MODE 使用手册（游戏内关卡编辑）

> 适用版本：Unity 2022.3.36f1 ｜ 场景：`Assets/Scenes/Test_2_BitFlow.unity` ｜ 全部操作都在 **Play 模式**内完成，不需要打开任何编辑器窗口。
>
> **这是作者的编辑模式，不是玩家的工坊。** 玩家侧的说明（手牌、选关面板、导入导出、工坊 DONE/TEST）
> 在 **[PLAYER_GUIDE.md](PLAYER_GUIDE.md)**。两者的区别：BUILD MODE 给的是无限元件 + `F5` 存盘，
> 只对「没有手牌」的沙盒关开放；有手牌的关卡进来会被自动摘掉（否则手牌盘整排让位、点不动）。

## 一分钟上手

1. 打开场景，按 **Play**（初始停在 TICK 00，位流不跑）。
2. 按 **`B`** → 屏幕底部弹出 `BUILD MODE` 面板，进入编辑状态。
3. **滚轮**（或直接点面板上的按钮）选元件，**左键**在格子上放置 → 画面立刻重建；按住左键拖动可以连续铺一片。
4. 按 **`PLAY`**（或 `STEP`）验证能否跑通；不满意继续改，按 **`B`** 或 **`ESC`** 退出。

## 按键

### 进出模式

| 键 | 作用 |
|---|---|
| `B` | 进入 / 退出编辑模式（来回切换） |
| `ESC` | 退出编辑模式（仅在编辑状态下有效） |

### 选件

| 键 | 元件 | 说明 |
|---|---|---|
| `1` | 墙 | 位撞上即销毁 |
| `2` | 发射器 | 按序列吐位 |
| `3` | 接收器 | 收满且内容正确才算过 |
| `4` | 分流器 | 按值走两臂 |
| `5` | 非门 | 取反后输出 |
| `6` | 过滤器 | 只放行指定值 |
| `7` | 延迟器 | 比直通元件多停 N 拍，再从对面直行穿出 |
| `8` | 擦除 | 光标变红，左键点谁删谁 |

> 最省事的选件方式是**滚轮**：每滚一格就是下一个元件（含擦除），面板按钮也可以直接点。
> 按钮左侧的小色块就是这个元件在场景里的本体颜色；进入编辑模式时默认选中的是 `1` 墙。

### 编辑

| 操作 | 作用 | 备注 |
|---|---|---|
| 左键 | 在该格放置当前元件 | 该格已有元件会被**直接替换**；越界（网格外）不响应 |
| 左键按住拖动 | 连续铺一片 | 只在拖过**新格子**时生效，不会重复刷同一格 |
| 右键 | 删除该格元件 | 鼠标必须落在网格格子上 |
| 右键按住拖动 | 连续擦一片 | 适合快速清掉画错的一条线 |
| `X` / `Delete` | 删除鼠标下的那一格 | 键盘快捷方式 |
| 中键 或 `R` | 把该格元件**顺时针旋转 90°** | 空格不响应；墙转了也没有视觉变化 |

> 「擦除」选件时左键也是删除（光标会变红）。
> 拖动只在**按下时**开始：松开后再经过格子不会误删，避免手抖清掉一片。

### 存档

| 键 | 作用 |
|---|---|
| `F5` | 保存当前草稿到磁盘（JSON） |
| `F9` | 从磁盘读回自定义关卡（覆盖当前草稿） |

## 放下时的默认配置

| 元件 | 默认 | 按一次 `R` 之后 |
|---|---|---|
| 墙 | — | 无变化 |
| 发射器 | 朝**右**，序列 `1` ×1 | 朝**下** |
| 接收器 | 进料面**下**（位从下往上进入），需要 `1` ×1 | 进料面**左**（位从左往右进入） |
| 分流器 | `1` → **上**，`0` → **右** | `1` → **右**，`0` → **下** |
| 非门 | 输出朝**右** | 输出朝**下** |
| 过滤器 | 输出朝**右**，只放行 `1` | 输出朝**下**，仍放行 `1` |
| 延迟器 | 延迟 `1` 拍（比直通晚 1 tick，无朝向） | 无变化（不参与旋转） |

旋转时**主朝向和副朝向一起**顺时针转，所以分流器的两个臂保持 90° 夹角不变。

## 画面怎么看（不用悬停也能读）

关卡里每种元件都有固定形状，方向一律是「细杆 + 加宽的箭头头」，颜色语义全关统一 **青 = 1、橙 = 0**：

| 元件 | 外观 | 一句话读法 |
|---|---|---|
| 墙 | 高立方 | 撞上即碎，用来挡路 |
| 发射器 | 矮宽块 + 朝外箭头 + 一排小方块 | 小方块＝序列点阵，从左到右就是**真实发射顺序**；发出去的会变暗 |
| 接收器 | 中块 + 进料面箭头 + 顶部进度条 + 小方块 | 进度条＝收了多少，小方块＝**要收的序列** |
| 分流器 | 小块 + 两条臂 | **青色臂走 1、橙色臂走 0** |
| 非门 | 菱形本体 + 输出箭头 | 形状是斜的，一眼和别的元件区分开 |
| 过滤器 | 薄板本体 + 出口箭头 | 箭头颜色就是它放行的值（青=只放 1，橙=只放 0） |
| 延迟器 | 方底座 + 钢蓝齿轮柱 + 顶部刻度点 | 刻度点＝延迟几拍；位被卷进去，等够拍数再从对面出来 |

鼠标悬停时还会显示同一份信息的文字版（序列、重复次数、朝向、进料面等）。

## 编辑与播放的关系（务必知道）

- **每次改动都会立刻重建整关**，并把时间轴复位到 `TICK 00` 且处于**暂停**状态 —— 想验证就点 `PLAY` / `STEP`，不会出现"改到一半位流正在跑"的混乱。
- 编辑只作用于**内存里的草稿**：`Assets/Data` 下的关卡资产（ScriptableObject）**不会被修改**，退出 Play 后一切还原。
- `REPLAY` 会保留你的改动（重建的是编辑后的关卡），可以反复"改 → REPLAY → 再改"。
- 编辑出来的关卡和资产关卡走**同一套渲染与模拟管线**，所以不用怀疑"编辑器里能跑、资产里不能跑"。

## 游戏内改不了的东西

BUILD MODE 只负责**摆放与朝向**。以下内容目前没有游戏内 UI，只能改 `Assets/Data` 里的关卡资产或代码（`DemoLevels`）：

- 网格尺寸（宽 / 高）与 tick 节奏 —— 编辑时沿用进入模式那一刻的关卡参数；
- 发射器/接收器的**序列内容**与**数量**；
- 过滤器的**放行值**（新放的固定为 `1`，可用 `R` 改朝向但改不了放行值）；
- 关卡的显示名。

这些内容要改得多就走 JSON 通道（导出 → 手改 → 校验 → 导入/覆盖）：见 **[LEVEL_JSON.md](LEVEL_JSON.md)**。

## 存档位置与格式

`F5` 写入（目录不存在会自动创建）：

```
Application.persistentDataPath/ShiftGoLevels/custom_level.json
```

Windows 编辑器下通常是：

```
C:\Users\<用户名>\AppData\LocalLow\DefaultCompany\SHIFT_GO2026\ShiftGoLevels\custom_level.json
```

文件是 `JsonUtility` 生成的缩进 JSON：

```json
{
  "displayName": "LEVEL 01",
  "width": 9,
  "height": 7,
  "tickInterval": 0.35,
  "cells": [
    {
      "kind": 1,
      "x": 0,
      "y": 3,
      "primaryDir": 1,
      "secondaryDir": 2,
      "sequence": "1011",
      "count": 2,
      "passValue": 1
    }
  ]
}
```

字段对应关系：

- `kind`：`0` 墙 / `1` 发射器 / `2` 接收器 / `3` 分流器 / `4` 非门 / `5` 过滤器
- `primaryDir`、`secondaryDir`：`0` 上 / `1` 右 / `2` 下 / `3` 左
  （`primaryDir` = 发射朝向 / 接收器进料面 / 非门与过滤器输出 / 分流器 `1` 臂；`secondaryDir` 只有分流器的 `0` 臂在用）
- `sequence`、`count`：发射器的序列与重复轮数 / 接收器的目标序列与个数
- `passValue`：过滤器放行值（`0` 或 `1`）

手改 JSON 是安全的：坐标越界、`kind` / 方向枚举非法的格子会在读取时被**直接丢弃**，不会把整关读崩。

## 想关掉编辑功能

删掉 `BitFlowRunner.Awake` 里自动补组件的那一行：

```csharp
if (GetComponent<BitFlowBuildMode>() == null) gameObject.AddComponent<BitFlowBuildMode>();
```

或者把场景里已有的 `BitFlowBuildMode` 组件直接移除。删掉后其它逻辑不受影响，只是不再能用 `B` 进编辑模式。

## 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 按 `B` 没反应 | Runner 还没跑完 `Start`（`Definition` 为空）时会被忽略，稍等一下再按；若 Console 有 `[BitFlow] 没找到 BitFlowRunner`，说明场景里没有 Runner |
| 左键点了不放元件 | 鼠标压在了 HUD 面板/滑条上（面板区域内的点击不会穿透到网格）；或点在网格之外（越界直接忽略） |
| `R` 没反应 | 该格子上没有元件；或者放的是墙（旋转不改外观） |
| 滚轮不换件 | 鼠标压在 HUD 面板/滑条上时不响应；离开 UI 区域再滚 |
| 拖动没有连铺/连擦 | 要**按住不放**并拖过新的格子（同一格不重复刷）；松手后再划过不会生效 |
| `F9` 没反应 | 存档不存在或 JSON 损坏，面板状态行会提示，Console 里有 `[BitFlow] 自定义关卡读取失败` 警告 |
| 改完关卡"不生效" | 编辑结果只在 Play 期间的内存里；`F5` 存的也只是用户目录下的 JSON，`Assets/Data` 的资产不会变 |
| 位流不动 | 每次编辑都会自动暂停并回到 TICK 00，点 `PLAY` 或 `STEP` 继续 |

## 改完编辑逻辑后怎么验证

编辑层的纯 C# 逻辑（放置 / 替换 / 删除 / 旋转 / id 分配 / JSON 往返）由
`Assets/Scripts/Gameplay/BitFlow/Tests/EditMode/LevelDraftTests.cs` 覆盖；
画面的可读性（箭头头、序列点阵、分流器臂配色、非门菱形、发射器进度变暗）由
`Assets/Scripts/Gameplay/BitFlow/Tests/EditMode/ElementViewReadabilityTests.cs` 覆盖：

```
Window > General > Test Runner > EditMode > Run All
```

命令行等价方式（工程根目录）：

```powershell
& "D:\UnityHubNocn\Unity2022.3.36f1\Unity 2022.3.36f1\Editor\Unity.exe" -batchmode -nographics `
  -projectPath "d:\UnityHubLab\SHIFT_GO2026" -runTests -testPlatform EditMode `
  -testResults "_testresults.xml" -logFile "_unity_test.log"
```
